# 解析增量岭回归方法包 v0.1

## 目标

第一版方法包用于打通“方法卡 → 更新计划 → 执行 Agent 交付模型适配 → 有界算法调用 → 新参数和状态 → 验证证据”的最小链路。它不是适配任意模型交付物的一键更新器，也不替代更新执行 Agent。

## 方法定义

方法固定求解平方误差总和加 L2 权重正则。旧状态保存未正则化的 Gram 矩阵和特征-目标交叉乘积；新批次到达后分别累加，再用同一正则强度和 intercept 规则求解新参数。

普通最小二乘是 `lambda=0` 的特例。交叉熵、MAE、Huber、分位数损失、L1 参数正则和非线性模型均不属于该方法。

## 决策边界

更新决策 Agent 只有在下列事实已经确认时才能选择本方法：

1. 任务是同一回归任务上的新增样本；
2. 模型是仿射线性回归，而不是非线性网络中的任意 `Linear` 模块；
3. 输入维度、输出维度、特征顺序、目标语义和预处理保持不变；
4. 旧充分统计量存在，且能证明与当前参数一致；
5. 目标函数、正则强度和 intercept 规则在更新期间不变。

只有旧 checkpoint 不满足第四项。若无法从旧数据重建状态，决策 Agent 必须排除本方法或重新规划。

## 执行边界

执行 Agent 负责核实已交付模型的特征处理、目标函数、checkpoint 格式、数据读取、产物保存和评估约定。算法工具只接收规范化矩阵，不搜索上游未声明资产或读取任意数据路径。

执行顺序：

```text
已批准 UpdatePlan
  → 执行 Agent 核实交付模型和方法前提
  → inspect_incremental_ridge_state
  → 执行 Agent 将授权的新数据转换为契约矩阵
  → update_incremental_ridge
  → 保存新 checkpoint 与新状态，不覆盖原资产
  → 加载验证和指标评估
  → ExecutionResult
```

任一硬前提不成立时，不调用更新工具，返回带证据的重规划请求。

## 工具边界

两个 Pi 工具通过项目级 Extension 注册：

- `inspect_incremental_ridge_state`；
- `update_incremental_ridge`。

工具只返回 JSON 报告，不写文件。输入和输出均有大小上限；第一版最多支持 256 个输入特征和 64 个输出。大规模数据、流式输入和外部矩阵产物需在后续执行环境中单独设计。

更新请求必须携带任务、计划版本和 `UpdatePlan` 内容摘要。工具只检查绑定字段的格式，不判断计划是否已经由人类批准；批准门槛属于编排层。

## 验证要求

受控测试至少证明：

- 合法旧状态可通过检查；
- 增量解与旧、新数据合并后的一次性岭回归解一致；
- 输入状态不会被原地修改；
- 目标函数、特征契约、参数或摘要不一致时拒绝更新；
- `lambda=0` 的普通最小二乘特例可运行；
- 新状态递增版本并记录上游状态和请求摘要。

真实任务交付还必须由执行 Agent 证明新 checkpoint 可加载、原资产未覆盖，并在获授权的数据上完成新旧指标比较。
