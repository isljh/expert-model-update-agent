# 0005：采用声明式模型、配置和 checkpoint 交付

## 状态

已接受，取代依赖完整项目源码的模型项目理解流程，以及 0004 中“配置可选”的决定。

## 背景

上游只承诺交付专业模型和权重，不承诺交付原训练项目与训练过程。旧流程需要扫描项目、发现模型候选并还原创建调用链，与真实交付边界不一致。

仅有模型类和权重时，部分维度可以从张量形状推断，但 dropout、激活、stride、padding、注意力头数和条件分支等构造语义不能通用恢复，因此不得把权重反推作为正式协议。

## 决定

1. TaskInput v0.3 强制声明模型文件、构造配置和 checkpoint。
2. 构造配置采用固定 Schema，声明模型类、完整关键字构造参数和 checkpoint 加载约定。
3. 删除目标项目路径、checkpoint 发现授权、模型候选和项目理解 Skill。
4. 配置与 checkpoint 先经过只读安全检查，再由 validate_model_delivery 绑定证据。
5. 实际加载固定使用 weights_only 和 strict=true；任何不兼容键均视为失败。
6. 原模型资产只读，后续训练代码和新 checkpoint 由系统在独立工作区创建。

## 后果

- 前置流程更短且可机械验证；
- 上游不需要公开训练过程；
- 上游必须按交付协议补充完整构造信息；
- 不符合单文件 PyTorch 模型交付约定的模型需要后续扩展适配器；
- 导入模型文件的执行安全仍需操作系统级隔离。
