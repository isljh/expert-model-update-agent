## 背景

仓库已经确认了更新决策 Agent 与更新执行 Agent 的分工、工具边界、真实训练与评估的交付门槛，以及 Harness Engineering 原则。当前需要把这些原则收敛成第一版可执行的产品边界，为后续选择小型 PyTorch 验证项目提供依据。

本计划是“构建智能体系统”的工作记录，不是某次模型更新任务的 `UpdatePlan`。

## 本阶段范围

## 已作决定

1. 第一版原型采用 Pi 承载三个相互独立的 Agent Session；初期由人类切换 Session、批准计划和启动高成本阶段。
2. Pi 是可替换的 Harness 选择，不是业务契约的一部分；`TaskInput`、`UpdatePlan`、执行结果和审阅结果不得依赖 Pi 私有 Session 格式。
3. 第一版不实现自动“更新感知”，由人类明确创建需要更新的任务。
4. 四类契约先定义与序列化无关的逻辑字段和校验语义；具体采用 JSON、YAML 或其他格式，留到实现计划中决定。
5. 独立审阅是交付前的必经阶段；执行 Agent 的成功声明不是完成证据。
6. EWC 仅是首个案例候选，尚未成为系统永久支持范围或本阶段实现承诺。
