# 任务受理 v0 实现计划

## 计划状态

- **状态：** v0.2 已实现，待独立 Pi 行为复测
- **开始日期：** 2026-09-16
- **目标：** 将用户关于项目、原模型、新数据和更新原因的自然语言请求整理为可校验、可确认的 `TaskInput` 草案

## 范围

本轮实现：

1. 任务受理语义、阶段和完成条件；
2. `TaskInput` v0.2 的机器可读结构；
3. 从自然语言整理任务草案的 `task-intake` Skill；
4. 不依赖第三方包的结构与状态校验工具；
5. 将校验器注册为项目级 Pi Extension 工具；
6. 构建者侧的行为测试与自动化检查；
7. 产品规格和仓库导航对齐。

本轮不实现：

- 模型结构解析、数据画像或方法选择；
- 从自然语言自动生成 JSON 的独立服务；
- 表单界面、版本管理界面或自动 Session 编排；
- 训练、评估或 EWC 算法；
- 自动替用户确认任务内容。

## 设计决定

1. 同一个更新决策 Agent 先执行任务受理，再在 `TaskInput` 确认后调用只读分析工具开展策略规划，不增加“任务理解 Agent”。
2. `TaskInput` 是用户、Agent 和校验程序共同使用的契约，不是模型分析报告。
3. 用户原始中文原样保留；稳定键名使用英文，字段说明、内容和确认摘要可以使用中文。
4. 模型结构、数据分布等工具证据不写入初始 `TaskInput`，由后续分析记录和 `UpdatePlan` 引用。
5. 第一版使用 JSON 作为可执行样例格式；这只确定 `TaskInput` v0 的落地格式，不预先决定其他契约或服务接口。
6. Skill 负责语义整理和提问，两个 Python 工具分别负责 TaskInput 校验和资产预检；项目级 Pi Extension 只提供薄适配并注册 `validate_task_input` 与 `preflight_task_assets`。
7. v0.2 将必答问题严格限定为固定最小字段缺口；Agent 自行提出的问题最多 3 个，均为可跳过且不阻塞确认的选答问题。
8. 原模型只读是系统不变量；模型框架、结构、参数、训练入口和数据分布等可发现事实不向用户提问。
9. 用户声明的资产位置保存在 TaskInput；存在性、类型和可读性由独立的 `AssetPreflightReport` 记录，不把可变化的环境状态写回业务输入。

## 验收条件

- 合法草案能通过草案模式校验。
- 信息不完整的草案不能误通过已确认模式，错误信息应指出具体缺口。
- Skill 不调用模型结构分析，不选择增量学习方法，不修改项目，也不把假设当成事实。
- 产品规格、Schema、Skill 和校验器使用一致的字段名和状态值。
- 资产预检失败时不能请求最终确认；进入项目理解前必须重新预检并匹配当前资产声明。
- 必答问题只能对应固定最小字段缺口；可选问题不超过 3 个，未回答或跳过都不影响确认。

## 验证记录

- 构建者侧的草案、确认门槛、完整确认和 Schema 版本检查通过；测试输入、参考结果和详细输出保存在 Pi 工作区之外。
- Pi Extension 能被当前安装的 Pi 加载，`validate_task_input` 与 `preflight_task_assets` 均注册成功；资产预检已通过 Extension 适配层实际调用。
- `task-intake` Skill 结构检查通过。
- 工作区内 Markdown 相对链接检查通过。
- 未安装新的第三方依赖；未调用模型或数据分析工具，未修改或训练目标模型项目。
- 资产预检的通过、失败、执行错误、checkpoint 发现授权、可选配置、摘要绑定和相对路径场景均已检查；它只打开目录或文件的只读句柄，不扫描内容、不解析配置、不导入项目代码、不加载 checkpoint。
- Skill 已声明任务受理阶段禁止命令行、目录扫描、编辑和写入；Pi Harness 的阶段级工具权限尚未实现，因此该禁止目前还不能由运行环境机械强制。
